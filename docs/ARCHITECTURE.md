# 架构与恢复策略

## 安装状态机

`输入校验 → 建立/恢复会话 → 解析发行版 → 精确匹配 Java → 下载并校验 → 安装加载器 → 写入安全配置 → 一次性组件验证 → 自动纠错 → 清理 → 纯净复测 → 交付`

任何状态失败都会：

1. 保留完整异常链、时间、来源、HTTP 状态、进程退出码和服务端输出；
2. 在安全范围内重试或切换来源/兼容参数；
3. 对已下载的完整文件做哈希复用，对 `.part` 做断点续传；响应体连续 20 秒无新数据时主动断开半死连接，从现有断点重连，连续失败后切换来源；
4. 无法恢复时停止后续变更，并给出面向用户的建议及日志路径。

会话状态写入 `.pilot-session.json.tmp` 后原子替换正式文件。状态包括阶段、运行/失败/取消/完成、最后异常、兼容性测试结果和自动纠错记录。同一版本/类型的未完成会话才允许续作；已完成目录和其他目录不会被覆盖。

## 来源顺序

- Mojang：Mojang 官方 → BMCLAPI。
- Fabric：Fabric Meta 官方 → BMCLAPI Fabric Meta。
- Forge：Forge Maven 官方 → BMCLAPI Maven；安装器还会对新旧 CLI 形式各尝试一次。
- Paper：PaperMC Downloads Service v3。PaperMC 要求自定义 User-Agent，程序已设置。
- Java：Eclipse Adoptium → Azul Zulu。两者为独立供应商，不混用文件哈希。
- 测试组件：Modrinth 官方 API/CDN 的 spark；失败时不阻塞服务端安装，降级为加载器验证。
- Fabric 前置：Modrinth 官方 API/CDN 的 Fabric API，与 spark 一起做 SHA-512 校验和一次性清理。

国内镜像永远排在官方或上游权威源之后。下载结果必须通过上游提供的哈希/大小校验（上游未提供哈希的 Forge/Fabric 安装文件至少校验非空并由后续 Java 启动验证兜底）。

## Java 选择

原版优先读取 Mojang 版本详情中的 `javaVersion.majorVersion`。其他发行版按官方兼容边界选择，重点是“主版本精确匹配”，避免旧 Forge 在过新的 Java 上崩溃。

## 启动验证

程序直接使用 `ProcessStartInfo.ArgumentList` 启动 Java，不通过 PowerShell，也不依赖字符串拼接执行命令。就绪信号来自服务端控制台的 `Done (...)` 等已知标志；失败信号和超时会进入诊断器。成功后通过标准输入发送 `save-all` 与 `stop`，超时才终止进程树。

启动纠错最多执行有限次数，每一种动作最多一次，避免无限循环：

- EULA 未生效：在实际工作目录重写；
- 端口在预检后又被抢占：选择下一空闲端口并更新配置；
- JVM 无法保留内存：降至安全范围并重新生成启动参数；
- 测试模组冲突且基础错误不明确：隔离一次性组件和测试世界，验证加载器本身；
- 每次动作及失败输出尾部写入 `pilot-recovery-report.txt`。

## 服务端属性管理

中文属性面板先读取当前服务端实际生成的 `server.properties`，再结合 Minecraft
版本决定可编辑字段与难度/游戏模式的数字或名称格式。旧版本实际存在的 `pvp`、
`allow-nether` 等字段会显示；26.2 等不再提供这些字段的版本不会被强行写入无效键。
未知字段、注释和顺序保持不变，中文 MOTD 使用 Java Unicode 转义兼容旧版本。
保存前比较时间、大小和 SHA-256，避免覆盖运行中服务端或外部编辑器的新修改；
确认无冲突后创建 `server.properties.pilot-backup`，再通过同目录临时文件原子替换。
关闭正版验证必须经过显式风险确认，端口变化会同步到 `server-pilot.json`。

## 不能擅自自动化的边界

路由器端口映射和第三方隧道账号涉及外部凭证，不能靠“自动点下一步”安全完成。程序内联机向导显示局域网地址与监听状态。防火墙规则只在用户明确确认且通过 Windows UAC 后创建，并限定指定 Java、指定 TCP 端口和专用网络；不会整体关闭防火墙。交付配置保持 `online-mode=true`、RCON/Query 关闭，并建议白名单。
